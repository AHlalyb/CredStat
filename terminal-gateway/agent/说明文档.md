# CredStat 跳板 Agent 使用说明

## 一、功能概述

跳板 Agent 是 CredStat 系统的跳板转发组件，部署在**能直接访问目标设备**的网络中（如内网跳板机、堡垒机所在网段），为中心网关提供 TCP 隧道，使中心网关能够通过 Agent 间接访问到原本无法直连的目标设备（交换机、服务器、数据库等）。

适用场景：
- 中心网关与目标设备之间存在防火墙隔离，无法直接建立连接
- 目标设备位于内网，中心网关只能访问跳板机
- 需要通过统一的跳板出口访问多台设备

## 二、工作原理

```
浏览器 ──WebSocket──> 中心网关(terminal-gateway.exe) ──TCP──> Agent(agent.exe) ──TCP──> 目标设备
```

1. Agent 启动后监听一个 TCP 端口（默认 `19878`）
2. 用户在 CredStat 系统中配置「跳板目标」，类型选择 **Agent**，填写 Agent 所在主机 IP、端口、共享密钥
3. 设备绑定跳板目标后，连接设备时中心网关先连接 Agent，发送一行 JSON 连接请求：
   ```
   {"action":"connect","ip":"目标设备IP","port":"目标设备端口","token":"共享密钥"}
   ```
4. Agent 校验 token 通过后，代为连接目标设备的 IP:端口，成功则回复 `{"ok":true}`，随后进入裸 TCP 双向透传
5. Telnet/SSH 的协议协商与登录均由中心网关完成，**Agent 只负责纯字节转发**，不解析任何协议内容

## 三、环境要求

- Windows / Linux / macOS 均可运行（当前提供 Windows 版 `agent.exe`）
- 无第三方依赖，单文件运行
- Agent 所在主机需能**访问目标设备**（目标设备端口需可达）

## 四、部署步骤

### 1. 复制文件

将 `agent.exe` 复制到跳板机 / 内网可达主机上的任意目录（例如 `C:\CredStatAgent\` 或 `/opt/credstat-agent/`）。

### 2. 启动 Agent

**Windows（前台运行）**

```bat
agent.exe --listen :19878 --token 你的共享密钥
```

**Windows（后台运行，可选）**

```bat
start /b agent.exe --listen :19878 --token 你的共享密钥
```

**Linux / macOS**

```bash
./agent --listen :19878 --token 你的共享密钥
# 或注册为 systemd 服务（见下文）
```

启动成功后控制台会输出：

```
Agent 已启动，监听 :19878，token 校验: 已启用
```

### 3. 放行防火墙端口

确保 Agent 所在主机的防火墙放行监听端口（默认 `19878`）：

- **Windows 防火墙**：入站规则中允许 TCP 19878 端口
- **Linux iptables/firewalld**：
  ```bash
  firewall-cmd --add-port=19878/tcp --permanent && firewall-cmd --reload
  ```

### 4. 在 CredStat 中配置跳板目标

1. 登录 CredStat，进入「跳板目标」管理页面
2. 点击「新增」，类型选择 **Agent**，填写：
   - **名称**：任意便于识别的名称，如「内网跳板机-A」
   - **IP**：Agent 所在主机的 IP 地址
   - **端口**：Agent 监听端口（默认 19878）
   - **共享密钥**：与启动 Agent 时 `--token` 参数一致（可留空，但建议必填）
3. 保存后，在「设备管理」中为需要经跳板访问的设备绑定该跳板目标即可

> 注意：中心网关 `config.json` 中的 `agent_token` 也必须与 Agent 的 `--token` 一致，否则连接会被拒绝。

## 五、启动参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--listen` | `:19878` | 监听地址和端口。格式为 `IP:端口`，`IP` 留空表示监听所有网卡 |
| `--token` | 空 | 共享密钥。与中心网关 `config.json` 的 `agent_token` 一致；留空则不校验 token（不推荐） |

示例：

```bat
:: 监听所有网卡的 19878 端口，启用 token 校验
agent.exe --listen :19878 --token AbC123XyZ

:: 仅监听指定 IP（多网卡主机）
agent.exe --listen 192.168.1.50:19878 --token AbC123XyZ

:: 不校验 token（测试环境用，生产环境不建议）
agent.exe --listen :19878
```

## 六、配置为 Windows 服务（推荐生产环境）

> 说明：`agent.exe` 已**原生支持 Windows 服务模式**。当 Windows 服务管理器启动它时，程序会自动进入服务模式并正常响应 start/stop 控制（无需 NSSM 等第三方工具包装）。服务模式下日志写入 `agent.exe` 同目录的 `agent.log` 文件。

### 方法一：使用一键脚本（推荐）

同目录下已提供 `install-service.bat` 管理脚本，右键 **以管理员身份运行**，按提示操作即可：

```
1. Install and Start Service (Recommended)
2. Install Only (Do Not Start)
3. Start Service
4. Stop Service
5. Uninstall Service
6. View Service Status
0. Exit
```

安装过程中会提示输入：
- **Listen address**：默认 `:19878`，直接回车使用默认值
- **Shared token**：与 CredStat 跳板目标中的「共享密钥」保持一致，强烈建议设置

脚本会自动完成以下配置：
- 服务名称：`CredStatAgent`
- 启动类型：自动（开机自启）
- 服务异常退出后 5 秒自动重启
- 可重复运行（会先卸载旧服务再重建，用于修改监听地址或 token）

### 方法二：手动使用 sc 命令（管理员 CMD 执行）

要求：`agent.exe` 所在路径**不能包含空格**（推荐 `C:\agent`）。

```bat
:: 创建服务（注意 binPath= 与 start= 等号后必须有一个空格；
:: 整个 binPath 值用一对引号包裹，内部不要再用引号）
sc create CredStatAgent binPath= "C:\agent\agent.exe --listen :19878 --token 你的共享密钥" start= auto DisplayName= "CredStat Jump Agent"
sc description CredStatAgent "CredStat Jump Agent: TCP tunnel for gateway to target devices"
sc failure CredStatAgent reset= 86400 actions= restart/5000/restart/5000/restart/5000

:: 启动 / 停止 / 删除
sc start CredStatAgent
sc stop CredStatAgent
sc delete CredStatAgent
```

> 手动方式注意：
> - `binPath=` 的值中，可执行文件路径与参数作为一个整体被一对引号包裹；路径含空格时 `sc` 会解析失败，请将 `agent.exe` 放到无空格路径（如 `C:\agent`）
> - 若服务已在运行，修改参数前需先 `sc stop` 再 `sc delete` 重建
> - 修改 token 后，需同步更新 CredStat 跳板目标中的「共享密钥」并重启中心网关

## 七、配置为 Linux systemd 服务（可选）

创建 `/etc/systemd/system/credstat-agent.service`：

```ini
[Unit]
Description=CredStat Jump Agent
After=network.target

[Service]
ExecStart=/opt/credstat-agent/agent --listen :19878 --token 你的共享密钥
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

然后执行：

```bash
systemctl daemon-reload
systemctl enable --now credstat-agent
systemctl status credstat-agent
```

## 八、常见问题

### 1. 连接 Agent 失败

- 确认 Agent 已启动且端口监听正常（`netstat -an | findstr 19878`）
- 确认中心网关与 Agent 之间的防火墙/安全组已放行端口
- 确认 CredStat 跳板目标中填写的 IP、端口与 Agent 实际监听一致

### 2. 提示「token 校验失败」

- 跳板目标中的「共享密钥」与 Agent 启动参数 `--token` 不一致
- 中心网关 `config.json` 的 `agent_token` 与 Agent 的 `--token` 不一致
- 修改后需重启中心网关

### 3. 提示「连接目标失败」

- Agent 所在主机无法访问目标设备的 IP:端口（网络不通、端口未开）
- 可在 Agent 所在主机上先用 `telnet 目标IP 端口` 测试连通性

### 4. 如何验证 Agent 工作正常

在 Agent 所在主机执行：

```bat
:: 测试端口是否监听
netstat -an | findstr 19878
```

或使用 telnet 测试：连接到 Agent 端口后手动输入一行 JSON 请求并回车：

```
{"action":"connect","ip":"127.0.0.1","port":"22","token":"你的共享密钥"}
```

返回 `{"ok":true}` 即代表 Agent 工作正常。

### 5. 连接成功后再次连接失败 / 页面卡住

- 如果 Agent 是前台窗口方式运行（直接双击 `agent.exe`），**请关闭 CMD 的「快速编辑模式」**：
  右键 Agent 窗口标题栏 → 属性 → 选项 → 取消勾选「快速编辑模式」→ 确定。
  否则在窗口内点击内容会使程序暂停，新的连接无法被处理，表现为「连接不上」。
- 推荐改为注册为 Windows 服务运行（见第六节），彻底避免该问题。

### 6. 安全建议

- **务必设置 `--token` 共享密钥**，防止未授权主机利用 Agent 访问内网
- 通过防火墙限制只有中心网关的 IP 可以访问 Agent 端口
- Agent 部署在跳板机时，建议使用专用低权限账号运行
